# 怎样理解和介绍这个项目

## 先运行一次

解压交付的 ZIP，进入 counterexample-lab 文件夹，运行 `python3 -m backend.server`，打开 http://127.0.0.1:8765。页面按最终要求仅提供英文。先使用 Array sorting 的 Built-in demo 示例，不需要 Docker 或模型 API。

候选函数 `sorted(set(numbers))` 看起来能排序，但 set 删除了重复值。输入 `[0, 0]` 时，预期是 `[0, 0]`，实际是 `[0]`。这个输入就是反例。

## 你需要解释的五件事

1. **问题约定**：什么输入合法、什么输出才正确？排序不仅要求有序，还要保留每个元素出现的次数。
2. **参考实现**：工具为什么知道正确答案？排序用 sorted，查找用线性遍历，最大子数组用小规模穷举。这些实现故意简单、便于检查。
3. **输入生成**：随机种子固定伪随机序列，还额外包含空数组、重复值、负数等边界。教学例子在早期就会出错，因此不能把这几题的发现率当模型能力结论。
4. **缩减**：删除元素、简化数值。每次变化都重新验证约定和错误，严格减少 `(长度, 绝对值之和)`。只有重复成立的答案错误才被接受。
5. **独立验证**：给修复版本另一组输入，排除之前见过的例子。测试通过说明“没在这些测试上发现错误”，不说明“所有可能输入都正确”。

## 与课程的连接

| 已学内容 | 在项目中的位置 |
| --- | --- |
| CS 128：函数、容器、程序结构 | 任务定义、输入生成、模块接口 |
| CS 225：数组、搜索、复杂度 | 二分查找、比较简单和高效实现 |
| CS 173 / MATH 314：逻辑、证明 | 输入约束、不变量、缩减终止性 |
| STAT 400：概率统计 | 多次试验、误差、不确定性和公平比较 |

不用先掌握模型内部结构就能研究模型输出的程序。若后来想训练模型，再补线性代数、优化和机器学习基础。

## 建议阅读顺序

1. `backend/tasks.py`：先自己预测三个错误函数在哪种输入上失败。
2. `tests/test_engine.py`：看看测试具体在保证什么。
3. `backend/engine.py` 的 `check`、`generate_cases`、`shrink`、`verify`。
4. `backend/reports.py`：比较三种提示具体差在哪里。
5. `frontend/src/Results.tsx`：看后端证据怎样显示出来。
6. 最后阅读 `backend/execution.py`：区分算法原理和代码运行边界。

## 几个可以自己完成的练习

- 手算最大子数组例子 `[-4, -2, -7]` 的正确答案，解释为什么初始化为 0 有问题。
- 在纸上跟踪二分查找 `[2, 2, 2]`，理解“找到任意一个”与“找到第一个”的区别。
- 将缩减预算设为 1，再设为 100，比较预算耗尽时报告的状态。
- 增加一个新的边界样例，并写测试证明生成器仍然遵守题目约定。
- 不看实现，说明为什么每次严格降低非负整数度量可以防止缩减无限循环。
