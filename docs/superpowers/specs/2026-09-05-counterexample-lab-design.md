# Counterexample Lab：第一版设计

日期：2026-09-05

状态：用户已明确同意按此范围实现（2026-09-05）。

## 目标与交付

创建可在 Codex 中打开、可独立提交到 GitHub 的本地 Git 项目。第一版研究问题是：精简失败输入是否有助于模型修复数组算法？工具负责收集可复现证据，不预设实验结论，不宣称研究创新已经得到验证。

交付 React + TypeScript 界面、Python 后端、隔离运行器、自动化测试、英文 README、中文学习说明和 AGENTS.md。提供不包含依赖缓存或密钥的 ZIP。项目不依赖作者电脑上的技能绝对路径；AGENTS.md 描述项目结构、启动与测试方法，方便后续 Codex 接手。

## 功能范围

支持三个明确题目：排序、二分查找（返回目标首次出现的位置，不存在则 -1）、最大连续子数组和（输入非空）。每题定义 Python solve 函数的参数和返回类型，附可信参考实现和人工编写的错误示例。示例明确标注为教学用例，不假称来自真实模型。

流程：选择题目 → 选择内置示例或粘贴 Python 实现 → 设置种子与测试预算 → 搜索失败 → 缩减输入 → 检查轨迹 → 导出报告或复制修复提示 → 粘贴修复代码 → 独立验证。

第一版模型交互由用户复制提示、粘贴回答完成，不需要 API 密钥。三种提示共享同一任务与候选代码，分别仅告知失败、提供原始反例、提供缩减反例。自动调用模型、多用户账号、在线托管和论文结论不在第一版范围内。

## 架构与运行方式

- frontend/：React、TypeScript、Vite，展示编辑器、参数、输出对比、缩减轨迹、修复验证和报告下载。
- backend/：Python API、任务定义、确定性输入生成、差分测试、缩减器、提示构建和报告结构。
- runner/：Docker 镜像及固定 JSON 输入输出协议。仅执行候选代码，不持有参考答案或验证逻辑。
- tests/：任务边界、缩减不变量、可复现性、报告与 API 测试；Docker 可用时运行隔离执行集成测试。
- docs/：算法解释、实验方法、当前限制与后续研究路线。

开发服务只监听本机，前端通过代理访问后端。默认不配置云服务和 API 密钥。

当前环境未发现 Docker。内置演示只能调用受信任、预先定义的函数，不使用 eval 或执行粘贴内容。没有 Docker 时，自定义代码执行明确不可用，显示安装指引；不可静默改为宿主机 subprocess 执行。

## 执行与错误边界

自定义代码在一次性 Docker 容器中执行：禁用网络、非 root、只读根文件系统、限制进程数/内存/CPU/执行时长，丢弃额外能力，禁止提权，不挂载宿主目录或 Docker socket。通过标准输入传递代码和数据，并限制输入、输出大小。超时必须终止并清理容器。

这面向个人本地使用，不将普通 Docker 容器描述为适合公共恶意多租户服务的完整安全边界。

结果区分答案错误、候选异常、超时、非法输出和基础设施故障。只有可重复的答案错误进入第一版缩减流程；基础设施故障不得记录为算法失败。报告保留错误类别及实际测试预算。

## 搜索与缩减

使用固定种子的伪随机生成器和显式边界样例。生成器遵守任务约束：二分查找输入有序，最大子数组输入非空。参考实现保持简单，以小规模穷举或直接实现作为正确性依据。

先分块删除，再逐元素删除，最后简化数值；每次接受变化都重新检查题目约束和答案错误，并严格降低预先定义的大小度量，避免循环。更改输入后重新计算参考答案。二分查找缩减过程中保持有序性。

报告使用“缩减反例”，不承诺全局最小。如果耗尽测试预算，清楚显示未完成缩减。轨迹包含接受的输入、参考结果、候选结果和调用计数。

## 修复验证与研究导出

修复验证使用独立种子及额外边界样例，记录与发现阶段重复的输入数量；尽可能去除重复，若任务空间或预算限制无法达到请求数量则如实报告。有限测试通过不等于证明正确。

JSON 报告含版本、题目、代码及摘要、种子、预算、生成器配置、原始反例、缩减反例、缩减轨迹、耗时和验证结果。不只保存百分比，保留实际计数。报告导入或下载内容不执行。

实验说明要求固定模型与提示条件、记录模型版本、在独立任务上评估、重复试验，并报告失败与不显著结果。第一版提供研究所需的数据收集能力，不把少量教学示例包装成正式 benchmark。

## 界面

单页工作台：左侧任务与代码，中间测试配置及主要操作，结果区显示原始/缩减输入对比、正确/错误输出、轨迹与修复反馈。按用户最终指令，仅提供英文 UI，取消中文与语言切换。后端反馈、缩减步骤和模型提示也使用英文；另保留中文学习文档。小屏幕按流程垂直排列。

明确区分演示与自定义执行模式。运行中禁用重复提交，展示当前状态；失败保留用户代码并提供可操作的错误信息。避免不必要的重渲染，遵循用户指定的 vercel-react-best-practices。

## 验收

1. 无模型密钥可以完成内置示例的发现、缩减、提示生成和导出。
2. 同一题目、代码与种子产生相同测试输入；报告可复现。
3. 缩减反例合法且仍触发答案错误；正确实现不会被判为错误。
4. 验证修复使用独立测试，并清楚表达测试覆盖的局限。
5. 无 Docker 时不执行用户代码；有 Docker 时验证正常返回、异常、超时和容器清理。
6. 前端构建、核心自动化测试和浏览器主要流程通过；未能运行的检查明确列出。
7. README 能指导新用户安装、启动、测试和理解项目；ZIP 不含密钥、依赖目录或虚构研究结果。
