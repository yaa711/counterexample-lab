# 第一次项目：怎样准备面试讲解

## 注释写什么

代码里的英文注释解释设计理由、约束和代价；本文件用于中文学习。不要给每行代码加翻译，也不要背注释当答案。

值得注释：为什么选独立参考实现、为什么严格减小度量、为什么保留失败输入、为什么排除已见测试、为什么清理 Docker 容器。

不值得注释：`i += 1` 是“i 加一”、`setBusy(true)` 是“设置 busy 为 true”。这些文字不能解释你的设计。

## 五分钟演示顺序

1. **问题**：模型或人写的代码可能通过普通例子，但在边界输入上出错。这个工具帮助发现并缩小错误。
2. **具体例子**：`sorted(set(numbers))` 会丢失重复值。对 `[0, 0]`，预期 `[0, 0]`，实际 `[0]`。
3. **完整路径**：前端提交题目、代码、种子 → 后端生成输入 → 独立参考实现与候选代码分别计算 → 比较结果 → 缩减 → 用新测试验证修复。
4. **一个核心设计**：每次接受缩减，输入必须合法、错误重复出现、大小度量严格降低。
5. **限制**：有限测试不是证明；局部缩减不保证全局最小；内置例子不是模型评测数据；普通 Docker 也不等于面向公众的完备执行隔离。

## 容易被问住的细节

- **最大子数组参考实现复杂度**：当前枚举 O(n²) 个子数组，每次切片与求和最坏 O(n)，所以整体 O(n³)。生成输入最多 16 个元素，选择这份参考实现是为了简单、容易独立核验。候选正确版本是 O(n) 的递推。不能只数两层循环就说参考实现是 O(n²)。
- **缩减终止**：度量是 `(数组长度, 数值绝对值之和 + 目标绝对值)`，按元组顺序比较；接受的每一步都严格降低。整数输入和有限预算共同约束过程。
- **随机性**：固定生成器版本和种子有助于重现输入，但不保证外部模型输出可重复，也不保证任意用户代码确定性。
- **验证泄漏**：换种子仍可能生成旧输入，因此显式排除搜索和缩减阶段的输入。同一实验反复点验证会复用验证集，不能拿它无限调参。
- **网络隔离测试**：不能假定无网络容器只会显示一个接口。应检验外部路由/连接能力和实际配置；本项目测试使用保留的 TEST-NET 地址。

## 第一周的三个练习

1. 不运行程序，手动写出 `[8, 3, 8]` 怎样变成 `[0, 0]`，解释每一步是否保留错误。
2. 自己给二分查找新增一个边界测试，并解释旧实现为什么返回错误下标。
3. 将最大子数组参考实现改成累计求和的 O(n²) 版本，用现有测试和独立小例子验证结果不变，再记录这次由你完成的修改。

每次改动后，记录“我原来以为什么、实验显示什么、我改了什么”。这些真实经历比背一份架构介绍更有说服力。
